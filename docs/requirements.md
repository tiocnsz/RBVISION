## 1. 项目概述

### 1.1 一句话定义
**RBVISION** 是一个面向**海康 VM (VisionMaster) 4.x** 的工业桥接模拟平台。它向上**模拟一个 GigE Vision 相机**给 VM 拉流,向下**模拟一台通用 6-DOF 机械臂执行器**,并提供**9 点 / N 点标定**功能,完成"图像坐标 ↔ 机械坐标"的双向映射。

### 1.2 项目边界

| 负责 (In Scope) | 不负责 (Out of Scope) |
|---|---|
| **GigE Vision 模拟相机**(推流给 VM 拉取) | 视觉目标识别 / 特征提取 (VM 做) |
| **通用 6-DOF 机械臂 3D 仿真执行器** | 真实机械臂的运动控制 / 伺服 |
| **9 点 / N 点标定**(图像坐标 ↔ 机械坐标) | AX=XB 6D 手眼标定 (VM 自己有) |
| **坐标转换服务**(VM 查表式调用) | 运动规划 / 逆运动学 (VM 做) |
| **正运动学**(用于显示 + 反馈关节角) | 视觉系统精度评估 (属于 VM) |
| **ModbusTCP 工业通信**(双向) | 其他工业总线 (OPC UA / Profinet 预留) |
| **示教模式**(GUI 控制机械臂末端) | 拖动示教 (PnP 形式) |
| **位置误差分析 / 轨迹回放** | — |

## 2. 用户场景

### 2.1 9 点标定流程 (Setup 阶段)
```
[用户/操作员]              [RBVISION]                  [海康 VM]
     │                          │                          │
     │ 1. 启动应用              │                          │
     │ 1.1 切换到示教模式       │                          │
     │ 1.2 GUI 控制机械臂末端  │                          │
     │     依次到 9 个 mark 点  │                          │
     │ 1.3 每个点按下"记录"    │ → 记录 (X_i, Y_i)        │
     │                          │                          │
     │                          │ 2. 通过 ModbusTCP 通知   │
     │                          │    VM 标定已就绪           │
     │                          │ ────────────────────────▶│
     │                          │                          │ 3. 拉 GigE 流
     │                          │                          │    识别 9 个
     │                          │                          │    mark 图像坐标
     │                          │                          │
     │                          │ 4. VM 通过 Modbus 发送   │
     │                          │ ◀────────────────────────│
     │                          │    9 个 (u_i, v_i)         │
     │ 5. 触发"计算"按钮       │                          │
     │ 6. 看到重投影误差         │ → 解算 3x3 仿射矩阵      │
     │                          │                          │ 7. VM 同步解算
     │                          │                          │    (双保险)
     │                          │ 8. 双方比较误差          │
     │                          │ ────────────────────────▶│
     │                          │                          │
     │                          │ 9. 标定完成,进入运行模式  │
```

### 2.2 运行阶段 (Run-time)
```
[海康 VM]                                [RBVISION]
   │                                         │
   │ 1. 拉 GigE 图像 → 识别目标               │
   │ 2. 通过 Modbus 查询"目标机械坐标"          │
   │ ────────────────────────────────────────▶
   │                                         │ 3. 查标定矩阵
   │                                         │    转换 (u,v) → (X,Y)
   │ 4. 收到 (X, Y) 机械坐标                  │
   │ ◀────────────────────────────────────────
   │ 5. 做运动规划(VM 内)                      │
   │ 6. 下发笛卡尔位姿指令 (x,y,z,rx,ry,rz)  │
   │ ────────────────────────────────────────▶
   │                                         │ 7. 做 FK 算关节角
   │                                         │ 8. 3D 动画驱动
   │                                         │ 9. 反馈实际关节角
   │ 10. 收到反馈(可选)                       │
   │ ◀────────────────────────────────────────
   │                                         │
   │ (循环直到任务完成)                        │
```

## 3. 功能需求

## 5. 接口协议

### 5.1 ModbusTCP

- 端口: 502 (默认,可配)
- 单元 ID: 1 (默认)
- 字节序: 大端 (Big Endian) — 与 VM 默认一致
- 寄存器映射: 见 FR-3.2 表格,详细见 `docs/modbus_register.md`

### 5.2 GigE Vision

- **GVCP Discovery** (UDP 3956): 响应 `DISCOVERY_ACK`
  - VendorName: `RBVISION`
  - ModelName: `RBVISION-Virtual-Cam`
  - SerialNumber: `RBV-0001`
  - UserDefinedName: 用户可配
  - IP: 本机 IP
- **GVSP 数据流** (UDP 3957): 块结构按 GigE Vision Standard 1.2
  - 默认: 1920x1080, Mono8, 25 FPS
  - 可配: 640x480 / 1280x720 / 1920x1080 / 自定义
- **像素格式**: Mono8 / RGB8 / BayerRG8
- **MTU**: 1500 字节

## 6. 技术选型

### 6.1 推荐技术栈

| 层 | 选型 | 版本 | 理由 |
|---|---|---|---|
| 语言 | Python | 3.10+ | 机器视觉生态最丰富 |
| GUI | PySide6 | 6.5+ | 工业级 Qt 绑定,LGPL 商用友好 |
| 3D 渲染 | VisPy | 0.14+ | PyOpenGL 包装,性能好,支持嵌入 Qt |
| 图像 / 标定 | OpenCV | 4.8+ | `cv2.calibrateHandEye` 备用,`cv2.estimateAffine2D` 仿射解算 |
| 数值计算 | NumPy + SciPy | latest | `scipy.optimize.least_squares` 用于仿射标定 |
| ModbusTCP | pymodbus | 3.6+ | 纯 Python,Server/Client 完整 |
| URDF | urdfpy | 1.1+ | URDF 解析 |
| 配置 | PyYAML | 6.0+ | 行业标准 |
| 日志 | loguru | 0.7+ | API 友好 |
| 测试 | pytest + pytest-qt | latest | 业界标准 |
| 打包 | PyInstaller | 6.0+ | 单文件/单文件夹可执行 |

### 6.2 关键 ADR

- **ADR-001**: Python 而非 C++
  - 原因: 开发效率 vs 性能,本场景 50Hz 远低于 Python 极限
  - 代价: 打包体积 ~200MB,启动 ~3s,可接受
- **ADR-002**: 9 点标定 (2D 仿射) 而非 AX=XB 6D 标定
  - 原因: 用户明确需求(9 点);VM 4.x 标定模块也是 9 点范式
  - 后续: 若需要 6D 标定,OpenCV `cv2.calibrateHandEye` 已内置
- **ADR-003**: 自实现 GVCP/GVSP 而非用 Aravis
  - 原因: 跨平台、纯 Python、便于集成 3D 渲染输出
  - 备选: Aravis(仅 Linux,增加外部依赖)
- **ADR-004**: 寄存器映射按"功能段"组织(0-99 标定 / 100-199 运动 / 200-299 反馈 / 300-399 状态 / 400-499 转换服务)
  - 原因: 段地址清晰,易于扩展,符合工业 Modbus 习惯
  - 代价: 部分地址空缺,但留作未来扩展

## 9. 风险点 (修订后)

| 风险 | 等级 | 应对 |
|---|---|---|
| **R1: VM 4.x GigE 兼容性** ⭐ | 🟠 高 | M5 期间早 POE 用 VM 4.x 实测枚举/拉流;不通过则降级为 GVSP-only(纯推流)或自签 RTSP |
| **R2: 9 点标定在 6DOF 机械臂上的精度** | 🟡 中 | 仿真数据先验证;真实场景下提示用户用 9 点覆盖工作空间;精度不够时建议加辅助点 |
| **R3: 3D 场景实时截图 → GigE 推流** 的延迟 | 🟡 中 | 渲染线程和推流线程解耦;截图走共享内存;默认 25FPS 足够 |
| **R4: Modbus 实时性 + 寄存器地址对齐** | 🟢 低 | 50Hz 远低于 Modbus 上限;字节序约定好即可 |
| **R5: VisPy 嵌入 Qt 线程** | 🟡 中 | M4 先做 spike 验证;备选 PyOpenGL + QOpenGLWidget |
| **R6: PyInstaller 打包** | 🟡 中 | M7 后期验证,预估打包体积/启动时间 |
